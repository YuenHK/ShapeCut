# 一鍵 2.5D 外形轉換與 UI 重設計

日期：2026-07-20

## 目標

將目前以工程檢查步驟為主的工具，改成面向一般使用者的一鍵式轉換工具。使用者只需放入 STL；網站自動分析模型、選擇精確或 2.5D 外形流程、產生通用 Laser Cut 幾何套件，最後只顯示結果與下載選項。

本設計不要求損壞的 STL 被重建成可信的封閉 3D 實體。當安全／進階修復無法通過時，系統改為提取可驗證的 2D 外形，明確標示模型已被簡化。

## 實測問題與根因

兩個使用者模型均可成功讀取，但包含大量原始拓撲問題，無法在不猜測模型意圖的情況下修復為安全 3D 實體。

### `Copy of Beyblade X Knight Fortress.stl`

- 37,116 個三角形、18,364 個頂點。
- 原始模型有 105 條非流形邊、63 個退化三角形、33 個重複三角形、12 條面方向不一致邊及 3,563 個三維自相交。
- 安全修復後仍有 41 條開放邊界、49 條非流形邊及 3,561 個三維自相交。
- 進階修復因非流形面扇無法安全拆分而被阻擋。

### `Copy of Beyblade X Knight Fortress Group.stl`

- 40,100 個三角形、19,843 個頂點。
- 原始模型有 82 條非流形邊、21 個退化三角形、33 個重複三角形、3 條面方向不一致邊及 1,165 個三維自相交。
- 安全修復後仍有 56 條開放邊界、79 條非流形邊、18 個退化三角形、10 條面方向不一致邊及 1,166 個三維自相交。
- 進階修復同樣因非流形面扇無法安全拆分而被阻擋。

現有安全阻擋屬正確行為；新功能不能以放寬 3D 安全檢查來偽稱模型已被修復。

## 使用者流程

頁面只提供一個主要操作：選擇或拖放 STL。

```text
上載 STL
  → 自動讀取與初步分析
  → 正常模型：沿用精確流程
  → 無法安全修復：自動切換 2.5D 外形模式
  → 自動產生通用外形切片
  → 驗證 2D 幾何與輸出套件
  → 顯示成功／需注意／失敗及下載按鈕
```

使用者不需要確認軸線、選擇修復方式、設定材料、接受分件建議或逐步導航。處理中上載另一個檔案會取消舊任務；逾時或資源超限會以可理解的失敗結果結束，不令頁面永久卡住。

## 自動決策

1. STL 成功解析後先執行現有安全檢查與安全修復。
2. 若修復後 3D 模型通過現有安全條件，沿用精確模型流程。
3. 若 3D 修復被任何拓撲、方向、自相交或工作量條件阻擋，自動改用 2.5D 外形模式，不要求使用者作額外選擇。
4. 兩種流程都必須產生相同的結果介面與通用幾何輸出格式；結果 metadata 記錄使用了 `exact` 或 `outline-2.5d` 模式。

## 2.5D 分層投影演算法

### 輸入與座標

- 使用可解析的有限座標三角形；不要求模型封閉、流形或無自相交。
- 使用現有候選軸線分析決定主要軸。若可信軸線不存在，使用模型最短包圍盒軸作為可重現的降級軸，並在結果中加入注意提示。
- 保留模型原始平面尺寸；不得悄悄重新縮放至任意大小。

### 分層投影

- 沿主要軸把模型範圍分成有限數目的高度層。
- 層數由模型高度、平面尺寸、目標細節容差及全域資源上限自動決定，而不是材料厚度。
- 把與每個高度範圍相交的三角形投影到該層的 2D 工作平面，建立佔用遮罩。
- 對遮罩執行有界的合併、閉合及細孔填補，以消除自相交、內部面及細小拓撲裂縫對外形的影響。
- 從清理後遮罩提取封閉輪廓，只保留面積最大的連通外形。所有較小分離外形、孔洞及內部細節均被忽略。
- 使用受容差及點數上限約束的輪廓簡化，移除 Laser Cut 無法可靠呈現的微小節點，同時限制相對尺寸偏差。

### 通用外形切片

- 每個高度層輸出一個可堆疊的最大封閉外輪廓。
- 不建立插槽、榫接或依賴材料厚度的壓配結構。
- 不設定雷射功率、速度、passes 或宣稱特定材料可安全生產。
- 使用者可用任何材料切割並以堆疊／黏合方式組裝；最終高度會隨實際材料厚度改變。
- manifest 記錄層次次序、模型原始高度位置、輪廓尺寸、簡化容差與注意事項。

## 2D 安全驗證

2.5D 結果不需要再次通過封閉 3D 實體檢查，但每個輸出輪廓必須通過獨立的 2D 製作前驗證：

- 所有座標有限且位於模型導出的有界範圍內。
- 輪廓封閉、至少有三個有效頂點、面積大於最小製作閾值。
- 輪廓沒有自相交、零長度邊或重複相鄰頂點。
- 簡化前後包圍盒及面積變化位於已定義容差內。
- 層數、每層節點數、遮罩尺寸、運算時間及記憶體使用均受明確上限約束。
- 排版後零件不得重疊或超出輸出工作區。
- 任何一項失敗都不得產生看似成功的製作套件。

## 結果狀態

### 成功

只有精確流程完成且沒有額外注意事項時使用。顯示下載按鈕及基本層數／尺寸摘要。

### 需注意

任何 2.5D 流程完成後都使用「需注意」，並必須清楚顯示：

- 「已簡化模型」；
- 原始內部細節、孔洞及細小分離零件已被忽略；
- 不同材料厚度會改變堆疊後高度；
- 輸出不包含雷射功率或速度；
- 正式製作前應先試切少量零件。

### 失敗

只在 STL 無法解析、沒有足夠有效投影外形、2D 輪廓無法通過驗證、資源超限或輸出套件驗證失敗時顯示。失敗頁須使用一般語言說明原因，並容許立即選擇另一個檔案。

## 輸出

成功或需注意狀態提供：

- ZIP 製作套件；
- SVG；
- DXF；
- PDF 預覽；
- JSON manifest。

所有格式必須引用同一組已驗證的輪廓、層次次序及來源 fingerprint。輸出不得包含本機絕對路徑、電郵、帳戶資料或未經使用者提供的材料生產參數。

## UI 設計

採用已批准的 A「清新工具」方向：薄荷綠與白色、高對比文字、圓角卡片、大型主要操作及簡單中文。

網站只保留三個主要狀態：

1. **上載**：大型拖放區、「選擇模型」按鈕及本機私隱說明。
2. **處理中**：單一進度條，以及「模型已讀取／正在簡化／正在產生切片／正在準備下載」狀態；不顯示工程參數。
3. **結果**：成功／需注意／失敗徽章、外形預覽、層數與尺寸摘要、主要 ZIP 下載按鈕及次要格式連結。

不設側欄、不顯示目前逐步 wizard、不要求使用者理解非流形、面扇或修復演算法。具體技術診斷保留在可下載 manifest 及可展開的「技術資料」區域，不阻礙主要操作。

## 架構邊界

- `outline-2.5d` domain：純函數式分層投影、遮罩清理、輪廓提取、最大連通外形選擇及簡化。
- automatic pipeline：協調解析、精確／2.5D 決策、取消、進度、輸出及結果狀態。
- worker boundary：所有高成本投影與輪廓運算在 geometry worker 內執行，支援真正終止及重新建立 worker。
- output validation：統一驗證 SVG／DXF／PDF／JSON／ZIP 使用相同輪廓與 provenance。
- simple UI：只消費 pipeline progress、result summary、preview 及 downloadable artifacts；不自行重複 domain 判斷。

## 測試與驗收

### 使用者模型

- `Copy of Beyblade X Knight Fortress.stl`：上載後自動完成 2.5D 外形流程，不要求人工修復或軸線確認；結果為「需注意」，可下載通用幾何套件。
- `Copy of Beyblade X Knight Fortress Group.stl`：同樣自動完成；每層只保留最大連通外形，忽略細小分離零件；結果可下載。
- 兩個 STL 只作本機驗收 fixture，不得加入 Git、公開 bundle 或影片 metadata。

### 正常模型回歸

- 現有有效、對稱 STL 仍使用精確流程，不得無故降級到 2.5D。
- 現有安全阻擋規則仍適用於聲稱為精確 3D 修復的結果。
- 現有 SVG、DXF、PDF、JSON、ZIP 及 project persistence 測試保持通過，或由等效的一鍵流程測試明確取代。

### 2.5D 性質測試

- 對開放、非流形、重疊、自相交及多組件模型產生有限、封閉、無自相交的最大輪廓。
- 投影及簡化對相同輸入具決定性。
- 層次順序及尺寸保持一致，不受三角形輸入次序影響。
- 極小、極大、空層、高節點及超預算輸入 fail closed。
- 取消後不再發布舊任務結果。

### UI／瀏覽器驗收

- 首頁只需一次檔案選擇即可開始。
- 使用者不需要點擊修復、軸線、下一步、材料、分件或輸出確認。
- 上載新檔案會取消前一個流程並顯示新進度。
- 成功、需注意及失敗三種結果可由鍵盤與螢幕閱讀器辨識。
- 1920×1080、一般手提電腦及手機寬度均保持可讀、可操作。
